# Existing contracts and public entry points

Paths and identifiers below refer to the [reconciled baseline](baseline.md). “Consumer” identifies code that reads the artifact, or the human consumer where executable support ends. Examples with exact source hashes are in the [Fe](fe110.md), [Ni/Cu](nicu.md) and [oxide](oxide.md) mappings.

## Scientific input and output contracts

| Group and owning module | Definition and accepted example | Output and actual consumer | Version or compatibility condition |

Project ID, objective, system, method, criteria. Task ID, stage, scope, exclusions, jobs and paths. | Human-maintained project and task descriptions. H7 question/ticket is a distinct downstream input to MKM `single_point.ticket_binding`. | Project has `version: 1`. No generic task-to-engine reader identified. Job IDs describe historical work. Merge only compatible records for the same reaction. Acceptance, source origin, method and applicability travel with the record. Partial intake is useful. |
| B · Catalyst identities, kinetic data and reaction network | [Catalysis schemas](../../../configs/catalysis) for project, material, phase, surface, interface and active site, assembled through [bundle](../../../configs/kinetics/bundle.schema.json). | C · Structure and calculation evidence, structure parsers and calculation registry | [POSCAR reader](../../../scripts/neb_agent/utils_structure.py), [VASP output readers](../../../scripts/neb_agent/utils_vasp.py), [registry definitions](../../../scripts/registry_schema.py). | D · Species and adsorption, adsorption workflow and reaction network | [Species schema](../../../configs/kinetics/species.schema.json), network builder and site catalog. Gas or adsorbed species with composition, charge, phase/location, structure reference, binding geometry and `site_occupancy`. Example `co2-bound` occupies one acid and one oxygen site. | Species fingerprints and site-specific footprints go into the network, balance checks, coverage analysis and allowed engine mappings. Adsorption candidates require separate evidence and review before use. | Identify configurations by structure and location as well as formula. A missing footprint is unresolved. One multidentate molecule can consume multiple site slots. Reviewed inventories require their own denominators. |
| E · Reaction and TS evidence, transition-state search, TS vibrational validation and reaction network | [Reaction schema](../../../configs/kinetics/reaction.schema.json), [builder](../../../scripts/reaction_network/builder.py), [VFA analysis](../../../scripts/ts_validation/analyze_vfa.py). Reactant/product coefficients, vacancy consumption/release, direction/reversibility, IS/FS IDs, TS treatment, method compatibility, NEB/DIMER output and assigned vibration review. | Versioned `reaction-network/1` with structural, energetic, kinetic and review decisions per reaction. Thermochemistry consumes state evidence, kinetic generation consumes the network. Fe CHCO is the partially qualified example. | V1 bundle or `network-definition/1` or partial mapping accepted by the builder. A derived snapshot has a content version. Element/charge/site balance, review of the TS and applicability of a rate law are independent checks. |
| F · Thermochemistry | [Frequency parser](../../../scripts/vasp_vibrations.py), [harmonic functions](../../../scripts/thermochemistry/harmonic.py), [engine](../../../scripts/thermochemistry/engine.py). Fe VFA 2260 illustrates a TS-local result. | Per-state ZPE, thermal enthalpy increment, entropy, Gibbs correction and compatible reaction/barrier differences or explicit missing terms. Builder binds the resulting evidence to state/reaction. | Integer-v1 intake and operation-specific output. Same reference, phase treatment, subspace, T and standard state for compared states. Exclude only qualified TS reaction coordinate. Gas requires appropriate gas conditions. Corrections in eV, entropy in eV/K. |
| G · Kinetic parameters and conditions, kinetic data | [Parameter schema](../../../configs/kinetics/kinetic_parameter.schema.json) and [generation](../../../scripts/kinetic_parameters/engine.py). Versioned network, scoped model review, T/P, standard states, forward/reverse law, gas orders, units, degeneracy, coverage terms, uncertainty and validity range. | `kinetic-dataset/1` with rates or precise missing fields. Eligible rows feed separate CATKINAS and Zacros table exporters. Fe missing-data report and Ni/Cu cycle illustrate both outcomes. | Review and parameters belong to exact network/reaction/reference. Irreversible steps can exclude the reverse direction. An unknown direction cannot be assumed irreversible. Coefficient units depend on gas order and pressure convention. |
| G · Native rate output and source terms, kinetic data | [V2.0](../../../configs/kinetics/rate_output_v2.schema.json), [V2.1](../../../configs/kinetics/rate_output_v2_1.schema.json), [source terms](../../../configs/kinetics/rate_source_terms_v2.schema.json), [network binding](../../../scripts/kinetic_data/network_binding.py). CATKINAS event/reference pair/s and KMC event/lattice/time each keep their declared basis. | Dispatch on `schema_version`. Strict 2.1 binds project, network content, reaction identities and row stoichiometry. Preserve rate coefficients separately from flux. Change a denominator only with compatible physical mapping. Preserve unknown directional components. |
| H · Native configurations, baseline MKM and surface KMC | [Assembly](../../../scripts/native_model.py), [CATKINAS renderer](../../../scripts/baseline_mkm/native.py), [Zacros renderer](../../../scripts/surface_kmc/native.py), [simulation run schema](../../../configs/kinetics/simulation_run.schema.json). Dataset plus engine-specific configuration (Ni/Cu coverages/feed or lattice, local events, energetics, initial entities). | Engine-specific native files, readback and manifest. Separately bound executable, plan, limits, review and runtime produce a receipt for adapters. `data1.mat` or Zacros trajectory streams are native outputs. | Supplied table must equal the approved dataset export. Assembly records `execution_authorized=False`. Eligibility, execution status, numerical convergence and scientific validity remain separately scoped. Plans and corrected bundles have their own byte hashes. |
| I · MKM results, baseline MKM | [Result reconstruction](../../../scripts/baseline_mkm/single_point_result.py), [analysis](../../../scripts/baseline_mkm/analysis.py), `mkm_analysis`, `mkm_coverage`, `mkm_drc` and `mkm_batch_drc` schemas under [kinetics](../../../configs/kinetics). Example Ni/Cu result, accepted receipt, normalization and paired perturbations. | Molecular coverage and occupied/vacant sites, product-specific selectivity, turnover per declared reference and bounded DRC ranking. Analysis/priority imports can consume these artifacts. | Result/analysis/perturbation formats are independently versioned. Selectivity requires feed/product and molar or other declared basis. DRC needs matched perturbations and stability evidence. Unknown density precludes absolute-area conversion. |
| I · KMC results and uncertainty, surface KMC and kinetic data | [Trajectory samples](../../../scripts/surface_kmc/trajectory_statistics.py), [rate adapter](../../../scripts/surface_kmc/rate_adapter.py), [source covariance](../../../scripts/kinetic_data/stoichiometric_sources.py). Archived process counters and species samples bound to times, event definitions and lattice inventory. | Sample-window event increments, population changes and rates on the native denominator. V2.1 consumers retain missing uncertainty or steady-state evidence. `source_covariance` propagates supplied covariance or explicitly independent variances. | Keep event count, signed progress, population change and statistical error as different observables. A single short trajectory lacks a reviewed stationary window and replicate ensemble. Archived CATKINAS single-point rate uncertainty is also unmeasured. |

## Public CLI and callable interfaces

Module names below are relative to `scripts`. CLI forms use `python -m scripts.<module>`. Uppercase arguments denote paths or IDs. API names are existing Python functions. Commands with output directories are inventory examples.

| Operation | Entry point | Input → output or limit |
| --- | --- | --- |
| Context and references | Project/task YAML have no verified generic CLI. `scientific_priority.benchmark.read_sources(root, sources)` is used by the priority fixture. | Named JSON/YAML path and raw hash → verified documents for that consumer. `artifact_io.sha256_file(path)` also works for raw structures and binary receipts. |
| Scientific Intake | `scientific_intake BASE [EVIDENCE ...] --operation electronic`; `report(documents, operation)` | Select electronic, zpe, thermochemistry, site_mapping or kinetic_handoff requirements and print the reaction assessment. |
| Exchange and identity | `multiphase_contracts BUNDLE`; `reaction_network DEFINITION --identity-report FILE` | Validate complete V1 bundle; report location/ownership for partial catalogs independently. |
| VASP and adsorption | `neb_agent.utils_structure.read_poscar`, `neb_agent.utils_vasp.parse_outcar`, `parse_oszicar`, [adsorption candidate entry point](../../../scripts/adsmind_lite/generate_adsorption_candidates.py) | Raw evidence parsers or separate evidence-gated structure construction. Preserve substrate, facet and active atom mapping. Building a new geometry is outside the inventory workflow. |
| TS and registry boundary | `ts_validation.analyze_vfa.analyze_vfa`, `ts_validation.validation_pipeline.evaluate_validation_pipeline`; `registry_write plan --db DB --manifest FILE` | Bound TS review and compatible calculation metadata → diagnostics or registry plan. Registry application and [TS execution gate](../../../scripts/ts_strategy_engine/execution_gate.py) own separate actions. |
| Reaction network | `reaction_network DEFINITION [--project-id ID] [--intake FILE] [--thermochemistry FILE] [--ts-review FILE]`; `reaction_network.builder.build_network` | Mapping/definition plus evidence → snapshot; optional `--output-dir` publishes a content-addressed version. Site proposal and confirmation use separate arguments. |
| Thermochemistry | `thermochemistry parse OUTCAR POSCAR`; `thermochemistry calculate BASE [EVIDENCE ...] --operation zpe`; `thermochemistry.engine.calculate` | Parse spectrum or assess corrections. `--ts-review` binds the assigned mode. `--operation thermochemistry` checks finite-temperature evidence. |
| Kinetics | `kinetic_parameters NETWORK [--models FILE] [--evidence FILE] --format missing`; `kinetic_parameters.engine.generate` | Output dataset, missing diagnostics or eligible engine tables using `--format dataset/catkinas/zacros` as separate choices. |
| MKM preparation and gate | `native_model catkinas DATASET CONFIG DIRECTORY`; `baseline_mkm.single_point.qualify`, `prepare`, `preflight` and `status` | Table + config → model text/readback. Ticket + executable/plan/decision checked at the separate single-point boundary. |
| KMC preparation and gate | `native_model zacros DATASET CONFIG DIRECTORY`; `surface_kmc.bridge_topology.read_audit`, `surface_kmc.oxide_control.render`, `surface_kmc.zero_event_review.prepare_request` / `check_reviewed_action` | Native lattice, mechanism, energetics, simulation and initial state when specified. Specialized oxide control binds its five inputs and one zero-event plan. |
| Archived rates | `baseline_mkm.rate_adapter.adapt` and `surface_kmc.rate_adapter.adapt`; `rate_output_v2 OUTPUT --qualified-network NETWORK [--reaction-id ID]` | Native receipts and bound inputs → V2.1 export; strict validator checks the supplied network and expected reaction scope. Legacy `--catalog-network` checks a narrower scope. |
| Analysis and sensitivity | `baseline_mkm.analysis.inspect_draft`, `analyze`, `analyze_observations`; [bounded DRC reporting](../../../scripts/baseline_mkm/drc_batch_report.py); `surface_kmc.trajectory_statistics.sampling_window` | Draft gaps, archived single-point results, measured inventory observations, paired sensitivity outputs or KMC time window → distinct analysis products. No evidence of a universal all-engine selectivity or DRC result. |

Verification examples and exact exercised entry points are listed in the [offline record](verification.md).
