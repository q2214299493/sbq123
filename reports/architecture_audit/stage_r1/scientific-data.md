# Scientific data ownership and contract assessment

## Definition, evidence and derived values

| Concept | Authoritative representation and consumer | Boundary or open point |
| --- | --- | --- |
| Material and project | `configs/catalysis/{catalyst_material,catalyst_project}.schema.json`, indexed and linked by `multiphase_contracts.validate_bundle`. The network carries identities | Structure-file hashes and Registry calculation IDs are evidence links. Native aliases have no authority over identity |
| Phase and exposed surface | `phase.schema.json`, `surface.schema.json`, `multiphase_contracts._check_catalog` and context checks | A bulk polymorph, facet/termination and model cell must be independently declared and linked. Fe-specific detectors are upstream and optional when a valid reviewed site manifest exists |
| Interface | `interface.schema.json`, `interface_phase_ids`, `check_interface_ownership`, `check_cross_phase_scope` | Declared participating surfaces/phases and provenance bound the contact. Spatial adjacency or event embedding needs engine-appropriate geometry |
| Site identity and inventory | `active_site.schema.json`, `reaction_network/site_review.py`, network catalog and reviewed `inventory`/reference capacities in coverage observations | Site class/ID, available sites on modeled count reference, specific lattice nodes and physical density are different quantities. Surface catalog IDs alone establish no count/density |
| Species and footprint | `species.schema.json` composition, charge, structural provenance, site-occupancy map (integer sites per molecule). `multiphase_contracts` and network catalog validate context | CATKINAS aliases and Zacros names/legs are adapter mappings. `molecular_coverage` computes shares only when capacity, count reference and footprint agree |

| Vibrational evidence and TS qualification | `vasp_vibrations.parse_frequency_outcar` owns raw parsed observations. `ts_validation` owns mode/scope/connectivity review and TS grading. `ts_strategy_engine.scientific_claims` authorizes scoped claims | Frequency presence and electronic convergence give different evidence. | Thermochemistry | `thermochemistry/{frequencies,harmonic,engine}`, `scientific_intake`. | Rate output | V2.0 and V2.1 in `configs/kinetics/`, `rate_output_v2.validate_rate_output_v2`, shared `kinetic_data.native_rate_output` | Explicit version, conditions, reaction rows, native denominator and provenance. | Species and site source terms | `rate_source_terms_v2.schema.json`, `kinetic_data.stoichiometric_sources` | Signed net progress weighted by species or vacancy stoichiometry. | CATKINAS result | `baseline_mkm/results.py`, `single_point_result.py`, `kinetic_analysis.py`, `rate_adapter.py` | MAT/log, normalized single-point result and independent source balances/qualification. | Zacros result | `surface_kmc/{trajectory_statistics,rate_adapter}`, native receipts and restart manifest | Counter deltas aligned by event and time → finite-window observations on a simulation cell. | Reactor source terms | Optional interface from the accepted ADR and `modules/reactor_simulation/README.md` | Use qualified species sources in a physical balance basis, e.g. mol/(m³·s), with explicit extent/normalization bridge, conditions and valid domain. No reactor ingestion or solver in audited code |
| Qualification and provenance | Owning workflow review, provenance schemas/references, `artifact_io`, execution receipts, Registry audit and State Handoff lifecycle | `accepted`, `eligible`, `reviewed`, module `Completed`, run completion and valid JSON answer different questions. Preserve native bytes, review and scope independently. State Handoff does not qualify kinetic science |

## V2.1 can remain the shared boundary

It already represents directional progress, optional coefficients, species and vacancy sources, native extent/time/denominator, and an explicit physical conversion. `rate_normalization.py` guards basis identity and conversion policy. `rate_units.py` uses the optional unit backend for dimensions and activity orders. V2.1 references stable common fields and shared source-term definitions from V2.0. Engine IDs in the envelope are metadata. Engine templates, caps, units claimed by vendor formats and result parsing belong at the adapter edge.

There is a confirmed network-binding gap. In `rate_output_v2.py:66–101`, network mode checks project, network version, version digest and site IDs. At lines 119–154 it checks progress and recomputes sources from the supplied rate rows. The CLI additionally verifies the raw network hash. Neither entry validates reaction row identity, parameter set or signed stoichiometry against the reactions of that exact network. The native builder at `kinetic_data/native_rate_output.py:23–48` does use the network to build the rows. A caller of the public validator can bypass that producer and pass a self-consistent altered envelope.

We replayed the published CATKINAS Phase 3.0 rate envelope against its byte-identical network, then independently changed one reaction ID (including its coefficient key), one parameter ID, and one product coefficient in separate copies. Recomputing the source rows yields internally consistent copies. The API and CLI accepted all three with the original network SHA-256. These were temporary audit probes. Existing archive/native data and the status of those outputs are unchanged. `tests/test_rate_dimensions.py::test_scoped_network_catalog_and_raw_hash` intentionally binds synthetic rates to a different network for a catalog-only assertion. A stronger entry point should preserve explicit shape-only use and define projection/subset semantics before reuse. [Repair R1-001](technical-debt.md#p0--correctness-and-permission)

The V2.1 API validates representation and arithmetic. It is not a membership proof for external files, the receipt/qualification sidecars, uncertainty or eligibility at another operating point. V2.1 emits no Reactor input by itself. A downstream handoff needs byte-bound qualification, reaction/network compatibility and evidence for converting its particular native basis. A KMC cell and a CATKINAS reference-site pair may share dimensions and still have different denominators. Retain examples and independent bridges rather than special-casing engines in the generic validator.

## Duplicate or overlapping implementation inventory

Keep the different gate/error policies and centralize only pure inventory arithmetic after characterization |
