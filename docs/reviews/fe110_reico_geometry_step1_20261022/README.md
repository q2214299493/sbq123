# Fe(110) REICO 小试第一步：随机几何生成

日期：2026-10-22。**完成本地 CPU 随机生成与距离/边界检查；得到 99 个起点，1 个家族达到尝试上限。没有优化、GPU、DFT、训练或模型晋升。**

用户本轮授权：采用文献的随机采样思想，把统一 1.5 Å 下限改为适合当前 Fe–C–H–O 体系的规则，开始第一步。此前约 300 个标注构型方案见 `docs/reviews/fe110_reico_pilot300_20261021/`。本步运行边界仅包含本地 CPU 几何准备，不改变现有 VASP 参数、模型和正在运行的计算。

## 方法和距离规则

借鉴 [REICO 原子随机生成](https://github.com/HuGroup-shanghaiTech/REICO/blob/main/REICO/randomGS.py)，针对当前 Fe(110) 任务做受限改造：**保持已经核验的 Fe45 晶胞、全部 Fe 初始坐标和底部 18 个固定 Fe；随机表面 C/O/H，不随机重建 Fe 晶体。** 这不是原文广域 Ag–Pd–C–H–O 势的完整复现。

先随机取表面横向中心，再独立随机各吸附原子的坐标；横向局部半宽 1.7 Å，中心覆盖整个周期晶胞。C/O 相对最高层 Fe 的高度范围为 1.2–3.6 Å，H 为 0.8–4.0 Å。周期距离由 ASE 最小镜像计算，适用于当前非正交面内晶胞。

下表是**生成阶段的初始防碰撞下限**，不是优化目标键长、已验证稳定范围或 DFT 收敛标准。用户已授权按当前体系调整；本步仅确认实现与这些规则一致，未以 DFT 验证数值的最优性。

| 元素对 | 下限 / Å | 元素对 | 下限 / Å |
| --- | ---: | --- | ---: |
| Fe–C | 1.60 | C–C | 1.10 |
| Fe–O | 1.55 | C–O | 1.05 |
| Fe–H | 1.30 | C–H | 0.85 |
| O–O | 1.05 | O–H | 0.80 |
| H–H | 0.60 | | |

补充边界：每个吸附原子须有一个 3 Å 内邻居；至少一个 C/O 距 Fe 不超过 2.8 Å；周期真空间隙不小于 8 Å。真空间隙是对含吸附原子的几何检查，不改变原基底的 15 Å 建模真空参数。正常 C–H 1.09 Å、O–H 0.97 Å 在针对性测试中可通过；短 H–Fe 等碰撞会被拒绝。

**不强制分子键图或价态。** C₂HO、C₂H₂O、C₂H₃、C₃H₂O 是组成标签；随机构型可以是离平衡、断键或成键中的原子环境，不能据此称为既定分子或稳定吸附终态。后续若作为完整 C₂/C₃ 分子的优化种子，必须另外核对连接关系。

## 实际生成结果

随机种子 42。生成前冻结 100 个完整轨迹家族及 80/10/10 分区；每个家族最多 20 次随机尝试，不根据模型能量或最终测试标签选择。先做 8 家族小样本并独立读回，再从已有记录恢复到完整计划，没有重复生成前 8 个。

| 组成 | 计划家族 | 实际起点 |
| --- | ---: | ---: |
| C₂HO | 15 | 15 |
| C₂H₂O | 20 | 20 |
| C₂H₃ | 15 | 15 |
| C₃H₂O | 50 | 49 |
| 合计 | 100 | 99 |

共 407 次随机尝试，308 次被几何或接触条件拒绝。`family_0084`（C₃H₂O，训练分区）在 20 次内未通过，主要是 C–C、C–O、C–H 短接触；全部坐标和原因保留，没有补齐或扩容。实际为训练 79、开发 10、最终测试 10 个家族；C₂ 50、C₃ 49。分区是未来轨迹的隔离安排，目前没有训练数据或标签。

独立读回全部 99 个 POSCAR 后确认：

- 元素顺序为 Fe/C/O/H，数量与各家族配置一致；底部 18 个 Fe 固定掩码全部保留。
- Fe 坐标最大写入/读回误差约 4.44×10⁻¹⁶ Å；晶胞保持不变。
- 全部符合上述元素对距离下限与边界条件；含吸附原子的周期真空间隙为 11.014–13.126 Å。
- 99 个保留表面高度和位置的精确几何键互不重复。该检查只涵盖周期平移和同元素置换；尚未进行完整表面对称近重复检查、SOAP 选择或优化轨迹去重。
- 299 个家族文件的原始字节哈希已核对，汇总见 `geometry_review.json`。原始结构与拒绝记录保存在主工作区，不随源码发布分支上传。

后续若每家族最多取 3 帧，当前 99 个起点最多贡献 297 帧；这只是上限，不承诺每条轨迹都产生 3 个合格标注构型。

## 文件与复现

- 配置：`configs/fe110_reico_pilot/geometry_v1.json`。
- 生成入口：`scripts/adsorption/reico_random_geometry.py`。
- 输出根目录：`calculations/fe110_reico_pilot300_20261022/geometry_v1/`。
- `plan.json`：生成前冻结的家族、分区、配置/基底/生成器 SHA256、ASE/NumPy 版本。
- `inputs/`：本次配置和清洁基底的原始字节副本。
- `families/family_NNNN/`：POSCAR（通过时）、全部尝试坐标与原因 `attempts.jsonl`、完成或失败记录 `family.json`。
- `summary_0008.json` 与 `summary_0100.json`：小样本和完整计划的不可变检查点。
- `preview_first4.png`：四种组成各一个起点的俯视和侧视图，原子编号从 1 开始，不绘制推断化学键。

在包含同一哈希基底、相同依赖版本的工作区运行：

```powershell
python -m scripts.adsorption.reico_random_geometry --config configs/fe110_reico_pilot/geometry_v1.json --output calculations/fe110_reico_pilot300_20261022/geometry_v1 --limit 8
python -m scripts.adsorption.reico_random_geometry --config configs/fe110_reico_pilot/geometry_v1.json --output calculations/fe110_reico_pilot300_20261022/geometry_v1
```

完整家族被核验后跳过；中断但尚无完成记录的家族按独立随机种子确定性重算，只接受字节相同的已存在输出。现有文件不一致、输入/生成器哈希或依赖版本变化时拒绝覆盖。已经耗尽预算的家族保留失败状态，不自动重试。发布分支不包含私人计算结构，因此在该分支执行单元测试不需要生产基底，实际生成需要主工作区的同哈希基底。
