# 545 帧独立纯力训练包与 CPU 预检

新训练包把冻结 536 帧与已审核的 9 个 DFT 单点合在一个独立目录。仍用原 78 帧开发集，开发数据库与采样元数据逐字节一致。53 帧保留测试与 16 帧观察隔离成员的清单和来源保持原样。新包只有训练和开发数据库。

目录为 `calculations/fe110_reico_pilot300_20261022/force545_training_package_20261119_v1`。

- `training_manifest.json`、`train.db`、`train_metadata.npz` 保存 545 帧训练顺序、原始力和采样概率。
- `provenance/increment9/` 保留 9 个增量的原始 OUTCAR、力表定位及隔离证据。
- `cpu_data_preflight.json` 绑定 545 个训练和 78 个开发数据库行的坐标、元素顺序、力、固定原子、角色权重及预算检查。
- `two_epoch_replay.json` 逐点记录两轮抽样位置。配置和数据文件由 `package_inventory.json` 绑定。

## 怎样让 9 帧都用上

现有采样每次从 545 帧中按相同概率抽取。同一帧可能被多次抽到。冻结随机种子 42 后，可以在 CPU 上预先知道哪几个数据库位置会被抽到。将新增帧放到两轮各抽中一次的位置，原 536 帧保持相对顺序，每帧权重仍为 1/545。两轮仍为 1090 次计划迭代。

MZ73 的原生 Fairchem 读取数据时会重排。用 545 行合成数据实测了该映射、配置解析与采样序列，再把序列逐项对应到本地真实数据库的行号。回放显示 9 帧在每轮各出现一次。该结果绑定当前数据库顺序、随机种子和已核验的运行环境，实际训练须跑满两轮。更换环境、顺序或种子时需重放核对。

## CPU 与执行边界

本地核对了 623 个真实数据库行，并用原生 Fairchem 在 MZ73 CPU 上严格载入冻结 536 模型。远端 CPU 采样检查使用合成数据，真实训练数据留在本地。没有模型前向、参数更新、GPU 分配或 DFT 提交。

配置沿用纯力训练、学习率 1e−5、batch 1、2 epoch。训练申请上限为单 GPU 30 分钟，无自动重试。审阅请求中的训练授权为 false，GPU 运行预检仍待后续授权。
