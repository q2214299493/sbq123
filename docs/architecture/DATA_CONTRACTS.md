# Scientific data contracts

| Boundary | Input, units and evidence | Output and exclusion conditions |
|---|---|---|
| Network → kinetic model | Balanced species, phase, site inventories, compatible thermal records and explicit model bindings | Versioned kinetic dataset. Each adapter owns its engine-specific pressure, site and serialization conventions. |
| Point/window → Integration | Qualified MKM point and KMC observation window, bound sources, exact identity, denominator and units | Six per-observable compatibility decisions. Missing evidence yields null for the dependent difference. Window exposure and counts retain their original units. |
| Rate observation | rate_observation(payload, network_path, conditions=..., target=..., rate_evidence=..., evidence=...) verifies the complete rate file, independently pinned replay, network bytes, conditions, normalization and mapping approval | kinetic-observation/1 with kind mkm_local_source or kmc_sampled_source. Values retain phase, sign and the entire denominator. Source, engine version, run and native-output reference accompany the result. Invalid evidence propagates insufficient_evidence and null species. Sampled rates alone establish neither a new window nor seed convergence. |
| Balance observation | balance_observation uses the validated Reactor call with mol/(m³·s), volume in m³, per-gas inlet and outlet in mol/s | instantaneous_gas_balance with all flows, volume and signed accumulation in mol/s. Conversion approval defaults to absent in production. |
| Interpretation | interpret_observation receives an observation and the digest independently retained from its trusted producer | A description of the point, sample or balance, its quantities and scope. A caller-generated digest cannot grant scientific approval. Comparison interpretation uses the existing six-observable format. |
| Discovery | proposals_for_observation receives the interpreted evidence through the checked observation path, a scoped objective, ranked-input evidence and an external destination | The observation-linked entry independently replays the pinned rate, checks the parent receipt, run, network, operating point and benchmark scope, and requires each named reaction to contribute to the specified observed species. Attribution failures reject the request before ranking. Observation proposals carry their replay evidence and are rechecked by verify; legacy planning records have a separate format. The linked report contains interpretation, candidate scopes, ranking and deferred reasons. Proposals carry report SHA, targets, review_required and execution_authorized=false. Owner review and a new execution decision govern any next job. |
| DRC | Positive baseline and two positive TOFs, matched symmetric TS perturbations, fixed operating point, branch, endpoints and prefactors | kinetic_data.local_sensitivity.central_difference implements the historical log derivative. Qualification of the perturbations stays with MKM. A single KMC trajectory or Reactor accumulation is insufficient. |

The result and observation SHA fields hash canonical JSON excluding their own identity field. Use an independently retained identity or a fresh evidence-checked computation when reading external artifacts. Observation copies preserve caller-input isolation. Historical approvals and raw rate evidence remain under their original authorities.

Observation-linked planning selects IS, TS and FS from one uniquely matched reaction record in the approved network. An endpoint descriptor carries its id, its reaction and field selector, and the canonical SHA-256 of that network record. The planning target hashes the descriptor. Historical synthetic label hashes remain usable when explicitly declared as mock frames. These identities qualify benchmark references only. They do not authenticate physical coordinates. A reversible step may use reverse direction with swapped endpoints and consistent local site geometry. New structures use structure_status=unverified_hypothesis and appear only in the deferred report. Unsupported unsigned targets also defer.

The ranking publisher retains reports and immutable issuance records under its own output directory. Reviewers supply this directory through trusted application configuration, independently of the submitted proposal. Keep publisher write access separate from submission of verification inputs. Reports hash canonical JSON and include the ranking inputs. Verification replays the ranking, selects exactly one issued candidate and checks its rank, reasons, score, row digest and complete projected proposal. Verification without the retained origin fails closed. A legacy record can be checked against its original independently pinned report by passing directory and expected_report_sha256; keep the original report in that directory's reports subdirectory. Legacy reports preserve their historical row evidence and may predate retention of raw ranking inputs. No historical receipt is backfilled.

Local event claims bind core and environment site IDs, occupancy and adjacency to the reviewed kinetic dataset for the same network and reaction. Reverse events exchange initial and final states and directional multiplicities. New catalog-compatible geometries may be explicitly deferred for owner review.

New ranking reports use scientific-priority/2. Each current issuance must have a positive JSON integer rank equal to the unique row position. Existing /1 reports with ranking inputs require the same issuance validation. Only a scientific-priority/1 report predating ranking-input retention may use the historical path, with its original canonical digest supplied independently by the reviewer.

Proposal geometry may use event_geometry, site_geometry, or both. Each supplied declaration must independently satisfy the same typed local-event schema. Dual declarations must have identical canonical JSON, including numeric types; member order in JSON objects is immaterial. The same rule applies during issuance and persisted verification.
