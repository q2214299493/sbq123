# Nine composable template groups

A project may begin with one research question and an evidence pointer. Each subsequent group becomes required by a particular operation. The V1 bundle itself retains its required collections. For incomplete inputs use the existing intake or draft-definition route.

| Logical group | Owned fields or existing document | Reference from the project | Independently useful with missing data |
| --- | --- | --- | --- |
| 1. General research project | Existing project/version/ID/objective, system, method/compatibility and success criteria; companion task contains scope, exclusions and status. | Task, catalyst identity, evidence inventory, network, conditions, requested observables and engine routes. Keep run approvals in their original records. | Supports planning before any result exists. Eight-role assembly is the [proposed convention](assembly.md). |
| 2. Catalyst system | V1 project/material/phase/surface/interface/site records, structural provenance, facet, site ownership. | Catalog artifact or network catalog via ID and digest. Keep site type, physical inventory and observation denominator identifiable. | An identity report accepts partial catalogs. Fe has an unresolved phase link. Multiple phases need explicit evidence for an interface. |
| 3. Structure and calculation evidence | Raw POSCAR/CONTCAR, OUTCAR/OSZICAR, calculation settings and registry mapping, reviews and IDs. | Role-specific path+SHA for geometry, energy, frequencies and review. Reuse one file for several roles when the scientific mapping justifies it. | Order, composition, masks and electronic evidence can be inspected before a Hessian exists. |
| 4. Species and adsorption | V1 species or partial network definition; phase, material/surface/interface, structural provenance, adsorption geometry, composition, charge, denticity/footprint. | Species ID scoped to the network/catalog; configuration-specific structure and review references. | Gas species can have empty site occupancy. Missing site assignment for an adsorbate stays unresolved. |
| 5. Elementary reactions and network | Directed reactants/products, vacancy coefficients, location, IS/TS/FS, reviewed direction, energy references, parameter IDs and validation state. | Snapshot file and `network_version`; link multiple intakes, TS reviews, decisions and site proposals with their subject bindings. | Draft topology, balances and electronic barriers can be reported independently of export readiness. |
| 6. Thermochemistry | Per-state raw spectrum or precomputed components, active subspace, T, standard state, phase model, scaling/soft-mode treatment, provenance. | One or more state/condition-specific intakes and TS mode review; point to correction output if already qualified. | Fe TS-only ZPE is valid in its scope. Missing endpoint terms keep reaction-level Gibbs quantities unavailable. |
| 7. Kinetic parameters and operating conditions | Parameter-set/kinetic dataset, law, units, orders, degeneracy, validity range and uncertainty. Versioned configuration specifies feed and observables at an operating point. | Network, dataset, model/review, conditions and normalization source. Multiple conditions can reference one network. | Missing-data report works on a draft. Total pressure alone cannot define species activities or a native denominator. |
| 8. MKM engine configuration | CATKINAS-specific table and `catkinas` configuration, species aliases, coverages, overall stoichiometry, turnover/selectivity basis, single-point plan and approval. | Exact dataset version and configuration. Link native model, receipt, raw output, optional analysis and DRC pairs by role. | Preparation/readback and archive analysis have separate entry points. A run still needs its own reviewed executable plan. |
| 9. KMC engine configuration | Zacros-specific event table, sites/neighbors, graph, local patterns, energetics, seed state, recording controls and execution limits. | Dataset and KMC config; link lattice, mechanism, simulation, state, plan, raw trajectory and receipt when present. | Structural matching and counting can finish before native initialization. An MKM site inventory does not establish KMC adjacency or occurrence normalization. |

## Artifact references and provenance

1. **Pin the bytes and their meaning.** Reuse the catalog [artifact definition](../../../configs/catalysis/common.schema.json) and the [priority fixture’s named source references](../../../tests/fixtures/multiphase/priority_benchmark.json). Preserve the original path base, raw SHA-256 and role. Paths inside archives require the archive identity and member name. A printed paper citation, job number or bare basename cannot reproduce a file binding.
2. **Distinguish file digest, domain version and approval digest.** [File hashing and canonical JSON](../../../scripts/artifact_io.py) provide different identities. The network builder and kinetic generator own their internal versions. A displayed `network_version` need not equal the raw file hash. Keep both when linking a snapshot. A plan explicitly bound to raw bytes must be checked as raw bytes, including line endings.
3. **Bind physical meaning.** Preserve state/structure, ordered atoms, calculation settings, energy convention, units, scope, temperature, standard state and uncertainty where applicable. A different POSCAR hash may be scientifically comparable only with an explicit correspondence review. Logical IDs can repeat across projects; bind the project and network before resolving a reaction or site.
4. **Keep source collections intact.** A reference to an existing snapshot reuses the catalog embedded in that snapshot. Do not reconstruct its JSON to “deduplicate” its internal records. Derived views may display missing fields, provenance and eligibility without becoming review evidence. Changed inputs need a fresh digest and any required review binding.
5. **Preserve version semantics.** Research YAML `version: 1`, integer-v1 Scientific Intake, `1.0.0` multiphase exchange, `reaction-network/1` and `kinetic-dataset/1` are independently versioned. V2.0/V2.1 describe rate *outputs*. V2.1 strict validation requires the exact network and expected reaction scope. Matching format prefixes or site labels do not confer cross-version compatibility.
6. **Preserve authority.** Retain original review, receipt and scope. Structure acceptance, TS grade, model eligibility, benchmark validation and native execution approval are distinct. A missing optional reference can be reported as unavailable. A supplied reference with the wrong digest invalidates dependent claims.

## Maintainability for another catalyst

A new material/facet/interface, species ID, occupancy footprint or site inventory can enter the existing contracts through data when its physics falls within the supported representation. Catalyst-specific geometry construction, a previously unsupported rate law, or a missing native representation must be demonstrated at the owning module before proposing code. The oxide example requires an explicit graph even when all inventory counts are known. The Fe example requires new scientific evidence even though the parser and thermochemistry engine already exist.

Only request the groups needed for an observable. A structure-only project needs neither engine. Two requested engines can reference the same eligible network and conditions while retaining different data, denominators, preparation and approvals. Shared catalyst identity alone establishes no conversion between their rates.
