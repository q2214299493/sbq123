# C07 实际研究审阅与端点就绪性

## 结论

R004388 的匹配 Fe45 联合端点尚未就绪。C07 的原始图、两枚氢的静态
对应和已准备输入的来源已核对；另找回了单独 C* 的本地 Fe45 来源，
不应再把额外 C 记成完全没有素材。可以进入既有输入及兼容性复核、共同
Fe45 框架下的联合端点构造需求审阅；缺少的具体产物是配对的
`C*+C07*` 反应物和精确 C4 图的 Fe45 产物侧，以及各自科学验收证据。

原始 CARE C4 网络 `/reactions/3009` 与 R004388 映射一致：
`BondBreaking / C-O`，原方向 `C4H2O* + * -> C* + C07*`。
保留方向 R 为 `C* + C07* -> C4H2O* + *`。C4 原图是
`[C]OC([C])[CH]`，额外 C 连到 O；逆向是 **C–O 成键**。
“C3→C4”描述碳数扩展，不能当作形成 C–C 键的碳骨架增长。
这修正了原方案中没有限定成键类型的“链增长”表述。

原 CARE 导出为 Fe48，六个吸附原子零基48–53；Fe45原始、修订、准备

POSCAR同哈希 `fc9fba03…`，不是两个起点。MolBlock 与 canonical
SMILES的重原子出现顺序不同；补显式 H 的编号也不能当原 MolBlock 行号。

C4保留C07子图后，原MolBlock新增C为4、仅邻接O3；分组CARE POSCAR
对应新增C51、O52、H53/H54（零基），并有原ASE到POSCAR的重排。
原始 atom_map 均为0，所以这些是图对应，不是反应轨迹级原子追踪或
TS/机理验收。将来生成两个52原子端点时，必须显式给出新的全原子映射。

沿已登记 C+H 构建清单找回的 `sources/C_long_bridge_CONTCAR` 实为
Fe45C（46原子），不是C+H候选本身。其历史哈希 `738bacbc…` 一致，
与C07晶胞最大差为0，底18Fe固定掩码相同。原始输出/力/电子/磁性和
方法兼容性未在本轮重验，不能据此把它升级为已验收联合端点。
